<dl>
<dt>
<span>
<span>
abs
</span>
</span>
<span>
(
</span>
<em>
<span>
<span>
number
</span>
</span>
</em>
,
<em>
<span>
<abbr>
<span>
/
</span>
</abbr>
</span>
</em>
<span>
)
</span>
<a>
¶
</a>
</dt>
<dd>
<p>
Return the absolute value of a number. The argument may be an integer, a floating-point number, or an object implementing
<a>
<code>
<span>
__abs__()
</span>
</code>
</a>
. If the argument is a complex number, its magnitude is returned.
</p>
</dd>
</dl>
<dl>
<dt>
<span>
<span>
aiter
</span>
</span>
<span>
(
</span>
<em>
<span>
<span>
async_iterable
</span>
</span>
</em>
,
<em>
<span>
<abbr>
<span>
/
</span>
</abbr>
</span>
</em>
<span>
)
</span>
<a>
¶
</a>
</dt>
<dd>
<p>
Return an
<a>
<span>
asynchronous iterator
</span>
</a>
for an
<a>
<span>
asynchronous iterable
</span>
</a>
. Equivalent to calling
<code>
<span>
x.__aiter__()
</span>
</code>
.
</p>
<p>
Note: Unlike
<a>
<code>
<span>
iter()
</span>
</code>
</a>
,
<code>
<span>
aiter()
</span>
</code>
has no 2-argument variant.
</p>
<div>
<p>
<span>
Added in version 3.10.
</span>
</p>
</div>
</dd>
</dl>
<dl>
<dt>
<span>
<span>
all
</span>
</span>
<span>
(
</span>
<em>
<span>
<span>
iterable
</span>
</span>
</em>
,
<em>
<span>
<abbr>
<span>
/
</span>
</abbr>
</span>
</em>
<span>
)
</span>
<a>
¶
</a>
</dt>
<dd>
<p>
Return
<code>
<span>
True
</span>
</code>
if all elements of the
<em>
iterable
</em>
are true (or if the iterable is empty). Equivalent to:
</p>
<div>
<div>
<pre>
<span>
</span>
<span>
def
</span>
<span>
</span>
<span>
all
</span>
<span>
(
</span>
<span>
iterable
</span>
<span>
):
</span>
<span>
for
</span>
<span>
element
</span>
<span>
in
</span>
<span>
iterable
</span>
<span>
:
</span>
<span>
if
</span>
<span>
not
</span>
<span>
element
</span>
<span>
:
</span>
<span>
return
</span>
<span>
False
</span>
<span>
return
</span>
<span>
True
</span>
</pre>
</div>
</div>
</dd>
</dl>
<dl>
<dt>
<em>
<span>
awaitable
</span>
</em>
<span>
<span>
anext
</span>
</span>
<span>
(
</span>
<em>
<span>
<span>
async_iterator
</span>
</span>
</em>
,
<em>
<span>
<abbr>
<span>
/
</span>
</abbr>
</span>
</em>
<span>
)
</span>
<a>
¶
</a>
</dt>
<dt>
<em>
<span>
awaitable
</span>
</em>
<span>
<span>
anext
</span>
</span>
<span>
(
</span>
<em>
<span>
<span>
async_iterator
</span>
</span>
</em>
,
<em>
<span>
<span>
default
</span>
</span>
</em>
,
<em>
<span>
<abbr>
<span>
/
</span>
</abbr>
</span>
</em>
<span>
)
</span>
</dt>
<dd>
<p>
When awaited, return the next item from the given
<a>
<span>
asynchronous iterator
</span>
</a>
, or
<em>
default
</em>
if given and the iterator is exhausted.
</p>
<p>
This is the async variant of the
<a>
<code>
<span>
next()
</span>
</code>
</a>
builtin, and behaves similarly.
</p>
<p>
This calls the
<a>
<code>
<span>
__anext__()
</span>
</code>
</a>
method of
<em>
async_iterator
</em>
, returning an
<a>
<span>
awaitable
</span>
</a>
. Awaiting this returns the next value of the iterator. If
<em>
default
</em>
is given, it is returned if the iterator is exhausted, otherwise
<a>
<code>
<span>
StopAsyncIteration
</span>
</code>
</a>
is raised.
</p>
<div>
<p>
<span>
Added in version 3.10.
</span>
</p>
</div>
</dd>
</dl>
<dl>
<dt>
<span>
<span>
any
</span>
</span>
<span>
(
</span>
<em>
<span>
<span>
iterable
</span>

<span>

</abbr>
</span>
</em>
<span>
)

¶

</p>
<div>
<div>
<pre>
<span>
</span>
<span>
def
</span>
<span>
</span>
<span>
any
</span>
<span>
(
</span>
<span>
iterable
</span>
<span>
):
</span>
<span>
for
</span>
<span>
element
</span>
<span>
in
</span>
<span>
iterable
</span>
<span>
:
</span>
<span>
if
</span>
<span>
element
</span>
<span>
:
</span>
<span>
return
</span>
<span>
True
</span>
<span>
return
</span>
<span>
False
</span>
</pre>
</div>
</div>
</dd>
</dl>
<dl>
<dt>
<span>
<span>
ascii
</span>
</span>
<span>
(
</span>
<em>
<span>
<span>
object
</span>
</span>
</em>
,
<em>
<span>
<abbr>
<span>
/
</span>
</abbr>
</span>
</em>
<span>
)
</span>
<a>
¶
</a>
</dt>
<dd>
<p>
As
<a>
<code>
<span>
repr()
</span>
</code>
</a>
, return a string containing a printable representation of an object, but escape the non-ASCII characters in the string returned by
<code>
<span>
repr()
</span>
</code>
using
<code>
<span>
\x
</span>
</code>
,
<code>
<span>
\u
</span>
</code>
, or
<code>
<span>
\U
</span>
</code>
escapes. This generates a string similar to that returned by
<code>
<span>
repr()
</span>
</code>
in Python 2.
</p>
</dd>
</dl>
<dl>
<dt>
<span>
<span>
bin
</span>
</span>
<span>
(
</span>
<em>
<span>
<span>
integer
</span>
</span>
</em>
,
<em>
<span>
<abbr>
<span>
/
</span>
</abbr>
</span>
</em>
<span>
)
</span>
<a>
¶
</a>
</dt>
<dd>
<p>
Convert an integer number to a binary string prefixed with “0b”. The result is a valid Python expression. If
<em>
integer
</em>
is not a Python
<a>
<code>
<span>
int
</span>
</code>
</a>
object, it has to define an
<a>
<code>
<span>
__index__()
</span>
</code>
</a>
method that returns an integer. Some examples:
</p>
<div>
<div>
<pre>
<span>
</span>
<span>
>>>
</span>
<span>
bin
</span>
<span>
(
</span>
<span>
3
</span>
<span>
)
</span>
<span>
'0b11'
</span>
<span>
>>>
</span>
<span>
bin
</span>
<span>
(
</span>
<span>
-
</span>
<span>
10
</span>
<span>
)
</span>
<span>
'-0b1010'
</span>
</pre>
</div>
</div>
<p>
If the prefix “0b” is desired or not, you can use either of the following ways.
</p>
<div>
<div>
<pre>
<span>
</span>
<span>
>>>
</span>
<span>
format
</span>
<span>
(
</span>
<span>
14
</span>
<span>
,
</span>
<span>
'#b'
</span>
<span>
),
</span>
<span>
format
</span>
<span>
(
</span>
<span>
14
</span>
<span>
,
</span>
<span>
'b'
</span>
<span>
)
</span>
<span>
('0b1110', '1110')
</span>
<span>
>>>
</span>
<span>
f
</span>
<span>
'
</span>
<span>
{
</span>
<span>
14
</span>
<span>
:
</span>
<span>
#b
</span>
<span>
}
</span>
<span>
'
</span>
<span>
,
</span>
<span>
f
</span>
<span>
'
</span>
<span>
{
</span>
<span>
14
</span>
<span>
:
</span>
<span>
b
</span>
<span>
}
</span>
<span>
'
</span>
<span>
('0b1110', '1110')
</span>
</pre>
</div>
</div>
<p>
See also
<a>
<code>
<span>
enum.bin()

<p>
Without arguments, return the list of names in the current local scope. With an argument, attempt to return a list of valid attributes for that object.
</p>
<p>
If the object has a method named
<a>
<code>
<span>
__dir__()
</span>
</code>
</a>
, this method will be called and must return the list of attributes. This allows objects that implement a custom
<a>
<code>
<span>
__getattr__()
</span>
</code>
</a>
or
<a>
<code>
<span>
__getattribute__()
</span>
</code>
</a>
function to customize the way
<code>
<span>

</span>
</code>
reports their attributes.
</p>
<p>
If the object does not provide
<a>
<code>
<span>
__dir__()
</span>
</code>
</a>
, the function tries its best to gather information from the object’s
<a>
<code>
<span>
__dict__
</span>
</code>
</a>
attribute, if defined, and from its type object. The resulting list is not necessarily complete and may be inaccurate when the object has a custom
<a>
<code>
<span>
__getattr__()
</span>
</code>
</a>
.
</p>
<p>
The default
<code>
<span>

</span>
</code>
mechanism behaves differently with different types of objects, as it attempts to produce the most relevant, rather than complete, information:
</p>
<ul>
<li>
<p>
If the object is a module object, the list contains the names of the module’s attributes.
</p>
</li>
<li>
<p>
If the object is a type or class object, the list contains the names of its attributes, and recursively of the attributes of its bases.
</p>
</li>
<li>
<p>
Otherwise, the list contains the object’s attributes’ names, the names of its class’s attributes, and recursively of the attributes of its class’s base classes.
</p>
</li>
</ul>
<p>
The resulting list is sorted alphabetically. For example:
</p>

</span>

</span>

<span>

</span>

</span>
<span>

</span>
<span>

</span>
<span>

</span>
<span>

</span>
<span>

</span>
<span>
'_clearcache', 'calcsize', 'error', 'pack', 'pack_into',
</span>
<span>
'unpack', 'unpack_from']
</span>
<span>
>>>
</span>
<span>

</span>
<span>
</span>
<span>

</span>
<span>
:
</span>
<span>
...
</span>

</span>
<span>
</span>

</span>

</span>
<span>

</span>
<span>

</span>
<span>
,
</span>
<span>

</span>
<span>
]
</span>
<span>

</span>
<span>

</span>
<span>

</span>
<span>

</span>
<span>

</span>

<em>

</em>

<code>
<span>

</span>
</code>

</p>

</span>
</a>

<code>
<span>

</span>

<em>
not
</em>
written back to the corresponding local variables or nonlocal cell references, and assigning, reassigning, or deleting local variables and nonlocal cell references does
<em>
not
</em>
affect the contents of previously returned dictionaries.
</p>
<p>

<code>
<span>

</span>
</code>

</p>
<p>

</span>

As mentioned in the
<a>
<span>
Overview
</span>
</a>
, Python distinguishes between binary and text I/O. Files opened in binary mode (including
<code>
<span>
'b'
</span>
</code>
in the
<em>
mode
</em>
argument) return contents as
<a>
<code>
<span>
bytes
</span>
</code>
</a>
objects without any decoding. In text mode (the default, or when
<code>
<span>
't'
</span>
</code>
is included in the
<em>
mode
</em>
argument), the contents of the file are returned as
<a>
<code>
<span>
str
</span>
</code>
</a>
, the bytes having been first decoded using a platform-dependent encoding or using the specified
<em>
encoding
</em>
if given.
</p>
<div>
<p>
Note
</p>
<p>
Python doesn’t depend on the underlying operating system’s notion of text files; all the processing is done by Python itself, and is therefore platform-independent.
</p>
</div>
<p>
<em>
buffering
</em>
is an optional integer used to set the buffering policy. Pass 0 to switch buffering off (only allowed in binary mode), 1 to select line buffering (only usable when writing in text mode), and an integer > 1 to indicate the size in bytes of a fixed-size chunk buffer. Note that specifying a buffer size this way applies for binary buffered I/O, but
<code>
<span>
TextIOWrapper
</span>
</code>
(i.e., files opened with
<code>
<span>
mode='r+'
</span>
</code>
) would have another buffering. To disable buffering in
<code>
<span>
TextIOWrapper
</span>
</code>
, consider using the
<code>
<span>
write_through
</span>
</code>
flag for
<a>
<code>
<span>
io.TextIOWrapper.reconfigure()
</span>
</code>
</a>
. When no
<em>
buffering
</em>
argument is given, the default buffering policy works as follows:
</p>
<ul>
<li>
<p>
Binary files are buffered in fixed-size chunks; the size of the buffer is
<code>
<span>
max(min(blocksize,
</span>
<span>
8
</span>
<span>
MiB),
</span>
<span>
DEFAULT_BUFFER_SIZE)
</span>
</code>
when the device block size is available. On most systems, the buffer will typically be 128 kilobytes long.
</p>
</li>
<li>
<p>
“Interactive” text files (files for which
<a>
<code>
<span>
isatty()
</span>
</code>
</a>
returns
<code>
<span>
True
</span>
</code>
) use line buffering. Other text files use the policy described above for binary files.
</p>
</li>
</ul>
<p>
<em>
encoding
</em>
is the name of the encoding used to decode or encode the file. This should only be used in text mode. The default encoding is platform dependent (whatever
<a>
<code>
<span>
locale.getencoding()
</span>
</code>
</a>
returns), but any
<a>
<span>
text encoding
</span>
</a>
supported by Python can be used. See the
<a>
<code>
<span>
codecs
</span>
</code>
</a>
module for the list of supported encodings.
</p>
<p>
<em>
errors
</em>
is an optional string that specifies how encoding and decoding errors are to be handled—this cannot be used in binary mode. A variety of standard error handlers are available (listed under
<a>
<span>
Error Handlers
</span>
</a>
), though any error handling name that has been registered with
<a>
<code>
<span>
codecs.register_error()
</span>
</code>
</a>
is also valid. The standard names include:
</p>
<ul>
<li>
<p>
<code>
<span>
'strict'
</span>
</code>
to raise a
<a>
<code>
<span>
ValueError
</span>
</code>
</a>
exception if there is an encoding error. The default value of
<code>
<span>
None
</span>
</code>
has the same effect.
</p>
</li>
<li>
<p>
<code>
<span>
'ignore'
</span>
</code>
ignores errors. Note that ignoring encoding errors can lead to data loss.
</p>
</li>
<li>
<p>
<code>
<span>
'replace'
</span>
</code>
causes a replacement marker (such as
<code>
<span>
'?'
</span>
</code>
) to be inserted where there is malformed data.
</p>
</li>
<li>
<p>
<code>
<span>
'surrogateescape'
</span>
</code>
will represent any incorrect bytes as low surrogate code units ranging from U+DC80 to U+DCFF. These surrogate code units will then be turned back into the same bytes when the
<code>
<span>
surrogateescape
</span>
</code>
error handler is used when writing data. This is useful for processing files in an unknown encoding.
</p>
</li>
<li>
<p>
<code>
<span>
'xmlcharrefreplace'
</span>
</code>
is only supported when writing to a file. Characters not supported by the encoding are replaced with the appropriate XML character reference
<code>
<span>
&#
</span>
<em>
<span>
nnn
</span>
</em>
<span>
;
</span>
</code>
.
</p>
</li>
<li>
<p>
<code>
<span>
'backslashreplace'
</span>
</code>
replaces malformed data by Python’s backslashed escape sequences.
</p>
</li>
<li>
<p>
<code>
<span>
'namereplace'
</span>
</code>
(also only supported when writing) replaces unsupported characters with
<code>
<span>
\N{...}
</span>
</code>
escape sequences.
</p>
</li>
</ul>
<p>
<span>
</span>
<em>
newline
</em>
determines how to parse newline characters from the stream. It can be
<code>
<span>
None
</span>
</code>
,
<code>
<span>
''
</span>
</code>
,
<code>
<span>
'\n'
</span>
</code>
,
<code>
<span>
'\r'
</span>
</code>
, and
<code>
<span>
'\r\n'
</span>
</code>
. It works as follows:
</p>
<ul>
<li>
<p>
When reading input from the stream, if
<em>
newline
</em>
is
<code>
<span>
None
</span>
</code>
, universal newlines mode is enabled. Lines in the input can end in
<code>
<span>
'\n'
</span>
</code>
,
<code>
<span>
'\r'
</span>
</code>
, or
<code>
<span>
'\r\n'
</span>
</code>
, and these are translated into
<code>
<span>
'\n'
</span>
</code>
before being returned to the caller. If it is
<code>
<span>
''
</span>
</code>
, universal newlines mode is enabled, but line endings are returned to the caller untranslated. If it has any of the other legal values, input lines are only terminated by the given string, and the line ending is returned to the caller untranslated.
</p>
</li>
<li>
<p>
When writing output to the stream, if
<em>
newline
</em>
is
<code>
<span>
None
</span>
</code>
, any
<code>
<span>
'\n'
</span>
</code>
characters written are translated to the system default line separator,
<a>
<code>
<span>
os.linesep
</span>
</code>
</a>
. If
<em>
newline
</em>
is
<code>
<span>
''
</span>
</code>
or
<code>
<span>
'\n'
</span>
</code>
, no translation takes place. If
<em>
newline
</em>
is any of the other legal values, any
<code>
<span>
'\n'
</span>
</code>
characters written are translated to the given string.
</p>
</li>
</ul>
<p>
If
<em>
closefd
</em>
is
<code>
<span>
False
</span>
</code>
and a file descriptor rather than a filename was given, the underlying file descriptor will be kept open when the file is closed. If a filename is given
<em>
closefd
</em>
must be
<code>
<span>
True
</span>
</code>
(the default); otherwise, an error will be raised.
</p>
<p>
A custom opener can be used by passing a callable as
<em>
opener
</em>
. The underlying file descriptor for the file object is then obtained by calling
<em>
opener
</em>
with (
<em>
file
</em>
,
<em>
flags
</em>
).
<em>
opener
</em>
must return an open file descriptor (passing
<a>
<code>
<span>
os.open
</span>
</code>
</a>
as
<em>
opener
</em>
results in functionality similar to passing
<code>
<span>
None
</span>
</code>
).
</p>
<p>
The newly created file is
<a>
<span>
non-inheritable
</span>
</a>
.
</p>

</span>

</a>

</p>

<p>
The type of
<a>
<span>
file object
</span>
</a>
returned by the
<code>
<span>
open()
</span>
</code>
function depends on the mode. When
<code>
<span>
open()
</span>
</code>
is used to open a file in a text mode (
<code>
<span>
'w'
</span>
</code>
,
<code>
<span>
'r'
</span>
</code>
,
<code>
<span>
'wt'
</span>
</code>
,
<code>
<span>
'rt'
</span>
</code>
, etc.), it returns a subclass of
<a>
<code>
<span>

</span>
</code>
</a>
(specifically
<a>
<code>
<span>

</span>
</code>
</a>
). When used to open a file in a binary mode with buffering, the returned class is a subclass of
<a>
<code>
<span>

</span>
</code>
</a>
. The exact class varies: in read binary mode, it returns an
<a>
<code>
<span>
io.BufferedReader
</span>
</code>
</a>
; in write binary and append binary modes, it returns an
<a>
<code>
<span>
io.BufferedWriter
</span>
</code>
</a>
, and in read/write mode, it returns an
<a>
<code>
<span>
io.BufferedRandom
</span>
</code>
</a>
. When buffering is disabled, the raw stream, a subclass of
<a>
<code>
<span>
io.RawIOBase
</span>
</code>
</a>
,
<a>
<code>
<span>
io.FileIO
</span>
</code>
</a>
, is returned.
</p>

See also the file handling modules, such as
<a>

</a>
,

<code>

</span>

<code>

</span>

</span>
</code>
</a>

</span>

</span>

.
</p>
</dd>

<dl>
<dt>
<span>
<span>
pow
</span>
</span>
<span>
(
</span>
<em>
<span>
<span>
base
</span>
</span>
</em>
,
<em>
<span>
<span>
exp
</span>
</span>
</em>
,
<em>
<span>
<span>
mod
</span>
</span>
<span>
<span>
=
</span>
</span>
<span>
<span>
None
</span>
</span>
</em>
<span>
)
</span>
<a>
¶
</a>
</dt>
<dd>
<p>
Return
<em>
base
</em>
to the power
<em>
exp
</em>
; if
<em>
mod
</em>
is present, return
<em>
base
</em>
to the power
<em>
exp
</em>
, modulo
<em>
mod
</em>
(computed more efficiently than
<code>
<span>

</span>
<span>
exp)
</span>
<span>
%
</span>
<span>
mod
</span>
</code>
). The two-argument form
<code>
<span>
pow(base,
</span>
<span>
exp)
</span>
</code>
is equivalent to using the power operator:
<code>
<span>

</span>
</code>
.
</p>
<p>
When arguments are builtin numeric types with mixed operand types, the coercion rules for binary arithmetic operators apply. For
<a>
<code>
<span>

</span>
</code>
</a>
operands, the result has the same type as the operands (after coercion) unless the second argument is negative; in that case, all arguments are converted to float and a float result is delivered. For example,
<code>
<span>

</span>
<span>
2)
</span>
</code>
returns
<code>
<span>
100
</span>
</code>
, but
<code>
<span>
pow(10,
</span>
<span>
-2)
</span>
</code>
returns
<code>
<span>
0.01
</span>
</code>
. For a negative base of type
<code>
<span>
int
</span>
</code>
or
<a>
<code>
<span>
float
</span>
</code>
</a>
and a non-integral exponent, a complex result is delivered. For example,
<code>
<span>
pow(-9,
</span>
<span>
0.5)
</span>
</code>
returns a value close to
<code>
<span>
3j
</span>
</code>
. Whereas, for a negative base of type
<code>
<span>
int
</span>
</code>
or
<code>
<span>
float
</span>
</code>
with an integral exponent, a float result is delivered. For example,
<code>
<span>
pow(-9,
</span>
<span>
2.0)
</span>
</code>
returns
<code>
<span>
81.0
</span>
</code>
.
</p>
<p>
For
<a>
<code>
<span>
int
</span>
</code>
</a>
operands
<em>
base
</em>
and
<em>
exp
</em>
, if
<em>
mod
</em>
is present,
<em>
mod
</em>
must also be of integer type and
<em>
mod
</em>
must be nonzero. If
<em>
mod
</em>
is present and
<em>

precision after the decimal point. If

</p>

</span>

<code>
<span>

</span>
</code>

<code>
<span>

</code>

<code>
<span>

</span>
</code>

<em>

</em>

<em>
ndigits
</em>

<code>
<span>
None
</span>
</code>

<em>

</em>

<p>

<span>

</p>

<span>

</code>

<code>
<span>

</code>

<code>
<span>

</span>
</code>

<a>
<span>

</span>
</a>
for more information.
</p>
</div>

<dd>
<p>
Return a proxy object that delegates method calls to a parent or sibling class of
<em>

</em>
. This is useful for accessing inherited methods that have been overridden in a class.
</p>
<p>
The
<em>

</em>
determines the
<a>
<span>

</span>
</a>
to be searched. The search starts from the class right after the
<em>

</em>
.
</p>
<p>
For example, if
<a>
<code>
<span>
__mro__
</span>
</code>
</a>
of
<em>

</em>
is
<code>
<span>

</span>
<span>
->
</span>
<span>
B
</span>
<span>
->
</span>
<span>
C
</span>
<span>
->
</span>
<span>
A
</span>
<span>
->
</span>
<span>

</span>
</code>
and the value of
<em>

</em>
is
<code>
<span>

</span>
</code>
, then
<a>
<code>
<span>

</span>
</code>
</a>
searches
<code>
<span>

</span>
<span>

</span>
<span>

</span>
<span>

</span>

</span>

.
</p>
<p>
The
<a>
<code>
<span>

<em>

</em>

<a>
<code>
<span>

</span>
</code>
</a>
and
<a>
<code>
<span>

</span>
</code>
</a>
. The attribute is dynamic and can change whenever the inheritance hierarchy is updated.
</p>
<p>
If the second argument is omitted, the super object returned is unbound. If the second argument is an object,
<code>
<span>

</span>
<span>

</span>
</code>
must be true. If the second argument is a type,
<code>
<span>

</span>
<span>

</span>
</code>
must be true (this is useful for classmethods).
</p>
<p>
When called directly within an ordinary method of a class, both arguments may be omitted (“zero-argument
<code>
<span>

</span>
</code>
”). In this case,
<em>

</em>
will be the enclosing class, and
<em>

</em>

<code>
<span>

</code>
). (This means that zero-argument
<code>
<span>

</span>
</code>
will not work as expected within nested functions, including generator expressions, which implicitly create nested functions.)
</p>
<p>
There are two typical use cases for
<em>
super
</em>
. In a class hierarchy with single inheritance,
<em>
super
</em>
can be used to refer to parent classes without naming them explicitly, thus making the code more maintainable. This use closely parallels the use of
<em>
super
</em>
in other programming languages.
</p>
<p>
The second use case is to support cooperative multiple inheritance in a dynamic execution environment. This use case is unique to Python and is not found in statically compiled languages or languages that only support single inheritance. This makes it possible to implement “diamond diagrams” where multiple base classes implement the same method. Good design dictates that such implementations have the same calling signature in every case (because the order of calls is determined at runtime, because that order adapts to changes in the class hierarchy, and because that order can include sibling classes that are unknown prior to runtime).
</p>
<p>
For both use cases, a typical superclass call looks like this:
</p>
<div>
<div>
<pre>
<span>
</span>
<span>

</span>
<span>

(
</span>
<span>
B
</span>
<span>
):
</span>
<span>

</span>
<span>
</span>
<span>

</span>
<span>
(
</span>
<span>
self
</span>
<span>
,
</span>
<span>
arg
</span>
<span>
):
</span>
<span>
super
</span>
<span>
()
</span>
<span>
.
</span>
<span>
method
</span>
<span>
(
</span>
<span>
arg
</span>
<span>
)
</span>
<span>
# This does the same thing as:
</span>
<span>
# super(C, self).method(arg)
</span>
</pre>
</div>
</div>
<p>
In addition to method lookups,
<a>
<code>
<span>
super()
</span>
</code>
</a>
also works for attribute lookups. One possible use case for this is calling
<a>
<span>
descriptors
</span>
</a>
in a parent or sibling class.
</p>
<p>
Note that
<a>
<code>
<span>
super()
</span>
</code>
</a>
is implemented as part of the binding process for explicit dotted attribute lookups such as
<code>
<span>
super().__getitem__(name)
</span>
</code>
. It does so by implementing its own
<a>
<code>
<span>
__getattribute__()
</span>
</code>
</a>
method for searching classes in a predictable order that supports cooperative multiple inheritance. Accordingly,
<code>
<span>
super()
</span>
</code>
is undefined for implicit lookups using statements or operators such as
<code>
<span>
super()[name]
</span>
</code>
.
</p>
<p>
Also note that, aside from the zero argument form,
<a>
<code>
<span>
super()
</span>
</code>
</a>
is not limited to use inside methods. The two argument form specifies the arguments exactly and makes the appropriate references. The zero argument form only works inside a class definition, as the compiler fills in the necessary details to correctly retrieve the class being defined, as well as accessing the current instance for ordinary methods.
</p>
<p>
For practical suggestions on how to design cooperative classes using
<a>
<code>
<span>
super()
</span>
</code>
</a>
, see
<a>
guide to using super()
</a>
.
</p>

</span>
</code>
</a>
and

</span>
</code>
</a>
.

</p>
<p>

</p>
<div>
<div>
<pre>
<span>
</span>
<span>

</span>

</span>

</span>
<span>

</span>
<span>

</span>
<span>
,
</span>
<span>
2
</span>
<span>
,
</span>
<span>
3
</span>
<span>
],
</span>
<span>
[
</span>
<span>
'sugar'
</span>
<span>
,
</span>
<span>
'spice'
</span>
<span>
,
</span>
<span>
'everything nice'
</span>
<span>
]):
</span>
<span>
...
</span>
<span>

</span>
<span>
(
</span>
<span>

</span>
<span>
)
</span>
<span>
...
</span>
<span>

</span>
<span>
(2, 'spice')
</span>
<span>
(3, 'everything nice')
</span>
</pre>

</div>
<p>
More formally:
<code>
<span>

</span>
</code>
returns an iterator of tuples, where the
<em>

-th tuple contains the
<em>

</em>
-th element from each of the argument iterables.
</p>
<p>
Another way to think of
<code>
<span>

</span>
</code>
is that it turns rows into columns, and columns into rows. This is similar to
<a>

</a>
.
</p>
<p>
<code>
<span>

</span>
</code>
is lazy: The elements won’t be processed until the iterable is iterated on, e.g. by a
<code>
<span>

</span>
</code>
loop or by wrapping in a
<a>
<code>
<span>

</span>
</code>
</a>
.
</p>
<p>

<code>
<span>

</span>
</code>

</p>
<ul>
<li>
<p>

<code>
<span>

</span>
</code>

</p>
<div>
<div>
<pre>
<span>
</span>
<span>
>>>
</span>
<span>

</span>
<span>
(
</span>
<span>

</span>
<span>
(
</span>
<span>
range
</span>
<span>
(
</span>
<span>
3
</span>
<span>
),
</span>
<span>
[
</span>
<span>
'fee'
</span>
<span>
,
</span>
<span>
'fi'
</span>
<span>
,
</span>
<span>
'fo'
</span>
<span>
,
</span>
<span>
'fum'
</span>
<span>
]))
</span>
<span>
[(0, 'fee'), (1, 'fi'), (2, 'fo')]
</span>
</pre>
</div>
</div>
</li>
<li>
<p>
<code>
<span>
zip()
</span>
</code>
is often used in cases where the iterables are assumed to be of equal length. In such cases, it’s recommended to use the
<code>
<span>
strict=True
</span>
</code>
option. Its output is the same as regular
<code>
<span>
zip()
</span>
</code>

</p>
<div>
<div>
<pre>
<span>
</span>
<span>
>>>
</span>
<span>
list
</span>
<span>
(
</span>
<span>
zip
</span>
<span>
((
</span>
<span>
'a'
</span>
<span>
,
</span>
<span>
'b'
</span>
<span>
,
</span>
<span>
'c'
</span>
<span>
),
</span>
<span>
(
</span>
<span>
1
</span>
<span>
,
</span>
<span>
2
</span>
<span>
,
</span>
<span>
3
</span>
<span>
),
</span>
<span>
strict
</span>
<span>
=
</span>
<span>
True
</span>
<span>
))
</span>
<span>
[('a', 1), ('b', 2), ('c', 3)]
</span>
</pre>
</div>
</div>
<p>
Unlike the default behavior, it raises a
<a>
<code>
<span>

</span>
</code>
</a>
if one iterable is exhausted before the others:
</p>
<div>
<div>
<pre>
<span>
</span>
<span>
>>>
</span>
<span>
for
</span>
<span>

</span>
<span>
in
</span>
<span>
zip
</span>
<span>
(
</span>
<span>
range
</span>
<span>
(
</span>
<span>
3
</span>
<span>
),
</span>
<span>
[
</span>
<span>
'fee'
</span>
<span>
,
</span>
<span>
'fi'
</span>
<span>
,
</span>
<span>
'fo'
</span>
<span>
,
</span>
<span>
'fum'
</span>
<span>
],
</span>
<span>
strict
</span>
<span>
=
</span>
<span>
True
</span>
<span>
):
</span>
<span>
...
</span>
<span>

</span>
<span>
(
</span>
<span>
item
</span>
<span>
)
</span>
<span>
...
</span>
<span>
(0, 'fee')
</span>
<span>
(1, 'fi')
</span>
<span>
(2, 'fo')
</span>
<span>

</span>
<span>
</span>
<span>

</span>

</span>

</span>

</p>
</li>
<li>
<p>
Shorter iterables can be padded with a constant value to make all the iterables have the same length. This is done by
<a>
<code>
<span>
itertools.zip_longest()
</span>
</code>
</a>
.
</p>
</li>
</ul>
<p>
Edge cases: With a single iterable argument,
<code>
<span>
zip()
</span>
</code>
returns an iterator of 1-tuples. With no arguments, it returns an empty iterator.
</p>
<p>
Tips and tricks:
</p>
<ul>
<li>
<p>
The left-to-right evaluation order of the iterables is guaranteed. This makes possible an idiom for clustering a data series into n-length groups using
<code>
<span>
zip(*[iter(s)]*n,
</span>
<span>
strict=True)
</span>
</code>
. This repeats the
<em>
same
</em>
iterator
<code>
<span>
n
</span>
</code>
times so that each output tuple has the result of
<code>
<span>
n
</span>
</code>
calls to the iterator. This has the effect of dividing the input into n-length chunks.
</p>
</li>
<li>
<p>
<code>
<span>
zip()
</span>
</code>
in conjunction with the
<code>
<span>
*
</span>
</code>
operator can be used to unzip a list:
</p>
<div>
<div>
<pre>
<span>
</span>
<span>
>>>
</span>
<span>
x
</span>
<span>
=
</span>
<span>
[
</span>
<span>
1
</span>
<span>
,
</span>
<span>
2
</span>
<span>
,
</span>
<span>
3
</span>
<span>
]
</span>
<span>
>>>
</span>
<span>
y
</span>
<span>
=
</span>
<span>
[
</span>
<span>
4
</span>
<span>
,
</span>
<span>
5
</span>
<span>
,
</span>
<span>
6
</span>
<span>
]
</span>
<span>
>>>
</span>
<span>
list
</span>
<span>
(
</span>
<span>
zip
</span>
<span>
(
</span>
<span>
x
</span>
<span>
,
</span>
<span>
y
</span>
<span>
))
</span>
<span>
[(1, 4), (2, 5), (3, 6)]
</span>
<span>
>>>
</span>
<span>
x2
</span>
<span>
,
</span>
<span>
y2
</span>
<span>
=
</span>
<span>
zip
</span>
<span>
(
</span>
<span>
*
</span>
<span>
zip
</span>
<span>
(
</span>
<span>
x
</span>
<span>
,
</span>
<span>
y
</span>
<span>
))
</span>
<span>
>>>
</span>
<span>
x
</span>
<span>
==
</span>
<span>
list
</span>
<span>
(
</span>
<span>
x2
</span>
<span>
)
</span>
<span>
and
</span>
<span>
y
</span>
<span>
==
</span>
<span>
list
</span>
<span>
(
</span>
<span>
y2
</span>
<span>
)
</span>
<span>
True
</span>
</pre>
</div>
</div>
</li>
</ul>
<div>
<p>
<span>
Changed in version 3.10:
</span>
Added the
<code>
<span>
strict
</span>
</code>
argument.
</p>
</div>
</dd>
</dl>
<dl>
<dt>
<span>
<span>
__import__
</span>
</span>
<span>
(
</span>
<em>
<span>
<span>
name
</span>
</span>
</em>
,
<em>
<span>
<span>
globals
</span>
</span>
<span>
<span>
=
</span>
</span>
<span>
<span>
None
</span>
</span>
</em>
,
<em>
<span>
<span>
locals
</span>
</span>
<span>
<span>
=
</span>
</span>
<span>
<span>
None
</span>
</span>
</em>
,
<em>
<span>
<span>
fromlist
</span>
</span>
<span>
<span>
=
</span>
</span>
<span>
<span>
()
</span>
</span>
</em>
,
<em>
<span>
<span>
level
</span>
</span>
<span>
<span>
=
</span>
</span>
<span>
<span>
0
</span>
</span>
</em>
<span>
)
</span>
<a>
¶
</a>
</dt>
<dd>
<div>
<p>
Note
</p>
<p>
This is an advanced function that is not needed in everyday Python programming, unlike
<a>
<code>
<span>
importlib.import_module()
</span>
</code>
</a>
.
</p>
</div>
<p>
This function is invoked by the
<a>
<code>
<span>
import
</span>
</code>
</a>
statement. It can be replaced (by importing the
<a>
<code>
<span>
builtins
</span>
</code>
</a>
module and assigning to
<code>
<span>
builtins.__import__
</span>
</code>
) in order to change semantics of the
<code>
<span>
import
</span>
</code>
statement, but doing so is
<strong>
strongly
</strong>
discouraged as it is usually simpler to use import hooks (see
<span>
</span>
<a>
<strong>
PEP 302
</strong>
</a>
) to attain the same goals and does not cause issues with code which assumes the default import implementation is in use. Direct use of
<code>
<span>
__import__()
</span>
</code>
is also discouraged in favor of
<a>
<code>
<span>
importlib.import_module()
</span>
</code>
</a>
.
</p>
<p>
The function imports the module
<em>
name
</em>
, potentially using the given
<em>
globals
</em>
and
<em>
locals
</em>
to determine how to interpret the name in a package context. The
<em>
fromlist
</em>
gives the names of objects or submodules that should be imported from the module given by
<em>
name
</em>
. The standard implementation does not use its
<em>
locals
</em>
argument at all and uses its
<em>
globals
</em>
only to determine the package context of the
<a>
<code>
<span>
import
</span>
</code>
</a>
statement.
</p>
<p>
<em>
level
</em>
specifies whether to use absolute or relative imports.
<code>
<span>
0
</span>
</code>
(the default) means only perform absolute imports. Positive values for
<em>
level
</em>
indicate the number of parent directories to search relative to the directory of the module calling
<code>
<span>
__import__()
</span>
</code>
(see
<span>
</span>
<a>
<strong>
PEP 328
</strong>
</a>
for the details).
</p>
<p>
When the
<em>
name
</em>
variable is of the form
<code>
<span>
package.module
</span>
</code>
, normally, the top-level package (the name up till the first dot) is returned,
<em>
not
</em>
the module named by
<em>
name
</em>
. However, when a non-empty
<em>
fromlist
</em>
argument is given, the module named by
<em>
name
</em>
is returned.
</p>
<p>
For example, the statement
<code>
<span>
import
</span>
<span>
spam
</span>
</code>
results in bytecode resembling the following code:
</p>
<div>
<div>
<pre>
<span>
</span>
<span>
spam
</span>
<span>
=
</span>
<span>
__import__
</span>
<span>
(
</span>
<span>
'spam'
</span>
<span>
,
</span>
<span>
globals
</span>
<span>
(),
</span>
<span>
locals
</span>
<span>
(),
</span>
<span>
[],
</span>
<span>
0
</span>
<span>
)
</span>
</pre>
</div>
</div>
<p>
The statement
<code>
<span>
import
</span>
<span>
spam.ham
</span>
</code>
results in this call:
</p>
<div>
<div>
<pre>
<span>
</span>
<span>
spam
</span>
<span>
=
</span>
<span>
__import__
</span>
<span>
(
</span>
<span>
'spam.ham'
</span>
<span>
,
</span>
<span>
globals
</span>
<span>
(),
</span>
<span>
locals
</span>
<span>
(),
</span>
<span>
[],
</span>
<span>
0
</span>
<span>
)
</span>
</pre>
</div>
</div>
<p>
Note how
<code>
<span>
__import__()
</span>
</code>
returns the toplevel module here because this is the object that is bound to a name by the
<a>
<code>
<span>
import
</span>
</code>
</a>
statement.
</p>
<p>
On the other hand, the statement
<code>
<span>
from
</span>
<span>
spam.ham
</span>
<span>
import
</span>
<span>
eggs,
</span>
<span>
sausage
</span>
<span>
as
</span>
<span>
saus
</span>
</code>
results in
</p>
<div>
<div>
<pre>
<span>
</span>
<span>
_temp
</span>
<span>
=
</span>
<span>
__import__
</span>
<span>
(
</span>
<span>
'spam.ham'
</span>
<span>
,
</span>
<span>
globals
</span>
<span>
(),
</span>
<span>
locals
</span>
<span>
(),
</span>
<span>
[
</span>
<span>
'eggs'
</span>
<span>
,
</span>
<span>
'sausage'
</span>
<span>
],
</span>
<span>
0
</span>
<span>
)
</span>
<span>
eggs
</span>
<span>
=
</span>
<span>
_temp
</span>
<span>
.
</span>
<span>
eggs
</span>
<span>
saus
</span>
<span>
=
</span>
<span>
_temp
</span>
<span>
.
</span>
<span>
sausage
</span>
</pre>
</div>
</div>
<p>
Here, the
<code>
<span>
spam.ham
</span>
</code>
module is returned from
<code>
<span>
__import__()
</span>
</code>
. From this object, the names to import are retrieved and assigned to their respective names.
</p>
<p>
If you simply want to import a module (potentially within a package) by name, use
<a>
<code>
<span>
importlib.import_module()
</span>
</code>
</a>
.
</p>
<div>
<p>
<span>
Changed in version 3.3:
</span>
Negative values for
<em>
level
</em>
are no longer supported (which also changes the default value to 0).
</p>
</div>
<div>
<p>
<span>
Changed in version 3.9:
</span>
When the command line options
<a>
<code>
<span>
-E
</span>
</code>
</a>
or
<a>
<code>
<span>
-I
</span>
</code>
</a>
are being used, the environment variable
<span>
</span>
<a>
<code>
<span>
PYTHONCASEOK
</span>
</code>
</a>
is now ignored.
</p>
