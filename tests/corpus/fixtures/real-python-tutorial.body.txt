<p>
<a>
Python 3's F-Strings: An Improved String Formatting Syntax
</a>
<span>
(52m)
</span>
</p>
</div>
<p>
Python
<strong>
f-strings
</strong>
offer a concise and efficient way to interpolate variables, objects, and expressions directly into strings. By prefixing a string with
<code>
f
</code>
or
<code>
F
</code>
, you can embed expressions within curly braces (
<code>
{}
</code>
), which are evaluated at runtime.
</p>
<p>
This makes f-strings faster and more readable compared to older approaches like the
<a>
modulo (
<code>
%
</code>
)
</a>
operator or the string
<a>
<code>
.format()
</code>
</a>
method. Additionally, f-strings support advanced string formatting using Python’s string
<a>
format mini-language
</a>
.
</p>
<p>
<strong>
By the end of this tutorial, you’ll understand that:
</strong>
</p>
<ul>
<li>
An f-string in Python is a string literal
<strong>
prefixed with
<code>
f
</code>
or
<code>
F
</code>
</strong>
, allowing for the
<strong>
embedding of expressions
</strong>
within
<strong>
curly braces
<code>
{}
</code>
</strong>
.
</li>
<li>
To include dynamic content in an f-string, place your expression or variable inside the braces to
<strong>
interpolate
</strong>
its value into the string.
</li>
<li>
An
<strong>
f-string error
</strong>
in Python often occurs due to syntax issues, such as
<strong>
unmatched braces
</strong>
or
<strong>
invalid expressions
</strong>
within the string.
</li>
<li>
<strong>
Python 3.12
</strong>
improved f-strings by allowing
<strong>
nested expressions
</strong>
and the use of
<strong>
backslashes
</strong>
.
</li>
</ul>
<p>
This tutorial will guide you through the features and advantages of f-strings, including interpolation and formatting. By familiarizing yourself with these features, you’ll be able to effectively use f-strings in your Python projects.
</p>

<h2>
Interpolating and Formatting Strings Before Python 3.6
<a>
</a>
</h2>
<p>
Before Python 3.6, you had two main tools for interpolating values, variables, and expressions inside string literals:
</p>
<ol>
<li>
The
<a>
string interpolation operator
</a>
(
<code>
%
</code>
), or modulo operator
</li>
<li>
The
<a>
<code>
str.format()
</code>
</a>
method
</li>
</ol>
<p>
You’ll get a refresher on these two string interpolation tools in the following sections. You’ll also learn about the string formatting capabilities that these tools offer in Python.
</p>

<h3>
The Modulo Operator (
<code>
%
</code>
)
<a>
</a>
</h3>
<p>
The modulo operator (
<code>
%
</code>
) was the first tool for string interpolation and formatting in Python and has been in the language since the beginning. Here’s what using this operator looks like in practice:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
name
</span>
<span>
=
</span>
<span>
"Jane"
</span>
<span>
>>>
</span>
<span>
"Hello,
</span>
<span>
%s
</span>
<span>
!"
</span>
<span>
%
</span>
<span>
name
</span>
<span>
'Hello, Jane!'
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
In this quick example, you use the
<code>
%
</code>
operator to interpolate the value of your
<code>
name
</code>
variable into a string literal. The interpolation operator takes two operands:
</p>
<ul>
<li>
A string literal containing one or more conversion specifiers
</li>
<li>
The object or objects that you’re interpolating into the string literal
</li>
</ul>
<p>
The
<strong>
conversion specifiers
</strong>
work as replacement fields. In the above example, you use the
<code>
%s
</code>
combination of characters as a conversion specifier. The
<code>
%
</code>
symbol marks the start of the specifier, while the
<code>
s
</code>
letter is the
<strong>
conversion type
</strong>
and tells the operator that you want to convert the input object into a string.
</p>
<p>
If you want to insert more than one object into your target string, then you can use a
<a>
tuple
</a>
. Note that the number of objects in the tuple must match the number of format specifiers in the string:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
name
</span>
<span>
=
</span>
<span>
"Jane"
</span>
<span>
>>>
</span>
<span>
age
</span>
<span>
=
</span>
<span>
25
</span>
<span>
>>>
</span>
<span>
"Hello,
</span>
<span>
%s
</span>
<span>
! You're
</span>
<span>
%s
</span>
<span>
years old."
</span>
<span>
%
</span>
<span>
(
</span>
<span>
name
</span>
<span>
,
</span>
<span>
age
</span>
<span>
)
</span>
<span>
'Hello, Jane! You're 25 years old.'
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
In this example, you use a tuple of values as the right-hand operand to
<code>
%
</code>
. Note that you’ve used a string and an integer. Because you use the
<code>
%s
</code>
specifier, Python converts both objects to strings.
</p>
<p>
You can also use dictionaries as the right-hand operand in your interpolation expressions. To do this, you need to create conversion specifiers that enclose key names in parentheses:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
"Hello,
</span>
<span>
%(name)s
</span>
<span>
! You're
</span>
<span>
%(age)s
</span>
<span>
years old."
</span>
<span>
%
</span>
<span>
{
</span>
<span>
"name"
</span>
<span>
:
</span>
<span>
"Jane"
</span>
<span>
,
</span>
<span>
"age"
</span>
<span>
:
</span>
<span>
25
</span>
<span>
}
</span>
<span>
"Hello, Jane! You're 25 years old."
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
This syntax provides a readable approach to string interpolation with the
<code>
%
</code>
operator. You can use descriptive key names instead of relying on the positional order of values.
</p>
<p>
When you use the
<code>
%
</code>
operator for string interpolation, you can use conversion specifiers. They provide some string formatting capabilities that take advantage of
<strong>
conversion types
</strong>
,
<strong>
conversion flags
</strong>
, and some characters like the period (
<code>
.
</code>
) and the asterisk (
<code>
*
</code>
). Consider the following example:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
"Balance: $
</span>
<span>
%.2f
</span>
<span>
"
</span>
<span>
%
</span>
<span>
5425.9292
</span>
<span>
'Balance: $5425.93'
</span>
<span>
>>>
</span>
<span>
print
</span>
<span>
(
</span>
<span>
"Name:
</span>
<span>
%s
</span>
<span>
\n
</span>
<span>
Age:
</span>
<span>
%5s
</span>
<span>
"
</span>
<span>
%
</span>
<span>
(
</span>
<span>
"John"
</span>
<span>
,
</span>
<span>
35
</span>
<span>
))
</span>
<span>
Name: John
</span>
<span>
Age: 35
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
In the first example, you use the
<code>
%.2f
</code>
conversion specifier to represent currency values. The
<code>
f
</code>
letter tells the operator to convert to a floating-point number. The
<code>
.2
</code>
part defines the precision to use when converting the input. In the second example, you use
<code>
%5s
</code>
to align the age value five positions to the right.
</p>
<div>
<p>
<strong>
Note:
</strong>
Formatting with the modulo operator is inspired by
<a>
<code>
printf()
</code>
</a>
formatting used in
<a>
C
</a>
and many other programming languages.
</p>
</div>
<p>
Even though the
<code>
%
</code>
operator provides a quick way to interpolate and format strings, it has a few issues that lead to common errors. For example, it’s difficult to interpolate tuples in your strings:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
"The personal info is:
</span>
<span>
%s
</span>
<span>
"
</span>
<span>
%
</span>
<span>
(
</span>
<span>
"John"
</span>
<span>
,
</span>
<span>
35
</span>
<span>
)
</span>
<span>
Traceback (most recent call last):
</span>
<span>
</span>
<span>
...
</span>
<span>
TypeError
</span>
:
<span>
not all arguments converted during string formatting
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
In this example, the operator fails to display the tuple of data because it interprets the tuple as two separate values. You can fix this issue by wrapping the data in a single-item tuple:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
"The personal info is:
</span>
<span>
%s
</span>
<span>
"
</span>
<span>
%
</span>
<span>
((
</span>
<span>
"John"
</span>
<span>
,
</span>
<span>
35
</span>
<span>
),)
</span>
<span>
"The personal info is: ('John', 35)"
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
This syntax fixes the issue, and now your string successfully shows the tuple of data. However, the syntax is hard to read, understand, and remember, isn’t it?
</p>
<p>
Another issue with the
<code>
%
</code>
operator is its limited formatting capabilities and the lack of support for Python’s
<a>
string formatting mini-language
</a>
, which provides a powerful tool to format your strings.
</p>

<h3>
The
<code>
str.format()
</code>
Method
<a>
</a>
</h3>
<p>
The
<code>
str.format()
</code>
method is an improvement compared to the
<code>
%
</code>
operator because it fixes a couple of issues and supports the string formatting mini-language. With
<code>
.format()
</code>
, curly braces delimit the replacement fields:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
name
</span>
<span>
=
</span>
<span>
"Jane"
</span>
<span>
>>>
</span>
<span>
age
</span>
<span>
=
</span>
<span>
25
</span>
<span>
>>>
</span>
<span>
"Hello,
</span>
<span>
{}
</span>
<span>
! You're
</span>
<span>
{}
</span>
<span>
years old."
</span>
<span>
.
</span>
<span>
format
</span>
<span>
(
</span>
<span>
name
</span>
<span>
,
</span>
<span>
age
</span>
<span>
)
</span>
<span>
"Hello, Jane! You're 25 years old."
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
For the
<code>
.format()
</code>
method to work, you must provide replacement fields using curly brackets. If you use empty brackets, then the method interpolates its arguments into the target string based on position.
</p>
<p>
You can manually specify the interpolation order by referencing the position of each argument to
<code>
.format()
</code>
using zero-based indices. For example, the code below switches the arguments to
<code>
.format()
</code>
in the target string:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
"Hello,
</span>
<span>
{1}
</span>
<span>
! You're
</span>
<span>
{0}
</span>
<span>
years old."
</span>
<span>
.
</span>
<span>
format
</span>
<span>
(
</span>
<span>
age
</span>
<span>
,
</span>
<span>
name
</span>
<span>
)
</span>
<span>
"Hello, Jane! You're 25 years old."
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
In this example, you use numeric indices to manually define the order in which you want to interpolate the values that you pass as arguments to
<code>
.format()
</code>
.
</p>
<p>
You can also use keyword arguments in the call to the method and enclose the argument names in your replacement fields:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
"Hello,
</span>
<span>
{name}
</span>
<span>
! You're
</span>
<span>
{age}
</span>
<span>
years old."
</span>
<span>
.
</span>
<span>
format
</span>
<span>
(
</span>
<span>
name
</span>
<span>
=
</span>
<span>
"Jane"
</span>
<span>
,
</span>
<span>
age
</span>
<span>
=
</span>
<span>
25
</span>
<span>
)
</span>
<span>
"Hello, Jane! You're 25 years old."
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
This example showcases how
<code>
.format()
</code>
interpolates keyword arguments by their names into the target string. This construct considerably improves your code’s readability compared to the previous example and to the examples using the
<code>
%
</code>
operator.
</p>
<p>
Finally, the
<code>
.format()
</code>
method allows you to use dictionaries to provide the values that you want to interpolate into your strings:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
person
</span>
<span>
=
</span>
<span>
{
</span>
<span>
"name"
</span>
<span>
:
</span>
<span>
"Jane"
</span>
<span>
,
</span>
<span>
"age"
</span>
<span>
:
</span>
<span>
25
</span>
<span>
}
</span>
<span>
>>>
</span>
<span>
"Hello,
</span>
<span>
{name}
</span>
<span>
! You're
</span>
<span>
{age}
</span>
<span>
years old."
</span>
<span>
.
</span>
<span>
format
</span>
<span>
(
</span>
<span>
**
</span>
<span>
person
</span>
<span>
)
</span>
<span>
"Hello, Jane! You're 25 years old."
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
In this example, you use a
<a>
dictionary
</a>
containing the data to interpolate. Then, you use the
<a>
dictionary unpacking operator (
<code>
**
</code>
)
</a>
to provide the arguments to
<code>
.format()
</code>
.
</p>
<p>
The
<code>
.format()
</code>
method supports
<strong>

<p>
F-strings joined the party in Python 3.6 with

<h2>
Upgrading F-Strings: Python 3.12 and Beyond
<a>
</a>
</h2>
<p>
Now that you’ve learned why f-strings are great, you’re probably eager to get out there and start using them in your code. However, you need to know that f-strings up to Python
<a>

</a>
have a few limitations regarding the expressions that you can embed in curly brackets and a few other details.

</a>

<a>

</a>
of Python
<a>

</a>
. In the following sections, you’ll learn about the limitations and how Python 3.12 fixed them.

</span>

In this example, you use direct names instead of dictionary lookups in the replacement fields. The only additional requirement is that you need to use the dictionary unpacking operator (

<h3>
Lazy Evaluation in Logging
<a>
</a>
</h3>
<p>
Providing
<a>
logging
</a>
messages is a common example of those use cases where you shouldn’t use f-strings or
<code>
.format()
</code>
. The
<code>
logging
</code>
module runs string interpolation
<a>
lazily
</a>
to optimize performance according to the selected logging level.
</p>
<p>
For example, you may have a hundred debugging messages but only ten warning messages in your code. If you use an f-string or the
<code>
.format()
</code>
method to construct your logging messages, then Python will interpolate all the strings regardless of the logging level that you’ve chosen.
</p>
<p>
However, if you use the
<code>
%
</code>
operator and provide the values to interpolate as arguments to your logging functions, then you’ll optimize the interpolation process. The
<code>
logging
</code>
module will only interpolate those strings that belong to the current and higher logging levels.
</p>
<p>
Consider the following example:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
import
</span>
<span>
</span>
<span>
logging
</span>
<span>
>>>
</span>
<span>
msg
</span>
<span>
=
</span>
<span>
"This is a
</span>
<span>
%s
</span>
<span>
message!"
</span>
<span>
>>>
</span>
<span>
logging
</span>
<span>
.
</span>
<span>
warning
</span>
<span>
(
</span>
<span>
msg
</span>
<span>
,
</span>
<span>
"WARNING"
</span>
<span>
)
</span>
<span>
WARNING:root:This is a WARNING message!
</span>
<span>
>>>
</span>
<span>
logging
</span>
<span>
.
</span>
<span>
debug
</span>
<span>
(
</span>
<span>
msg
</span>
<span>
,
</span>
<span>
"DEBUGGING"
</span>
<span>
)
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
In this example, you use the modulo operator syntax to create the logging message. Then, you pass the value that you want to interpolate as an argument to the logging functions. Because
<code>
WARNING
</code>
is the default logging level, only the messages at this level and higher will be logged. That’s why the
<code>
debug()
</code>
function doesn’t generate any output.
</p>
<p>
In the above call to
<code>
debug()
</code>
, the string interpolation never happens because you’re using a higher logging level. However, if you use
<code>
.format()
</code>
like in the code below, then the interpolation will always happen:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
<span>
<span>
</span>
</span>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>
<code>
<span>
>>>
</span>
<span>
msg
</span>
<span>
=
</span>
<span>
"This is a
</span>
<span>
{}
</span>
<span>
message!"
</span>
<span>
>>>
</span>
<span>
logging
</span>
<span>
.
</span>
<span>
debug
</span>
<span>
(
</span>
<span>
msg
</span>
<span>
.
</span>
<span>
format
</span>
<span>
(
</span>
<span>
"DEBUGGING"
</span>
<span>
)
</span>
</code>
</pre>
</div>
</div>
</code-block>
<p>
If you call
<code>
debug()
</code>
a million times inside a loop, then Python will eagerly evaluate its argument, and the interpolation will happen a million times. This behavior will add performance overhead to your code. That’s why the
<code>
logging
</code>
module does the interpolation lazily.
</p>
<p>
The lazy nature of how
<code>
logging
</code>
does string formatting can make a difference, and it’s only possible using the modulo operator.
</p>

<h3>
SQL Database Queries
<a>
</a>
</h3>
<p>
Using any string interpolation tool is a bad idea when you’re building SQL queries with dynamic parameters. In this scenario, interpolation tools invite
<a>
SQL injection attacks
</a>
.
</p>
<p>
To illustrate the problem, say that you’re working with a
<a>
PostgresSQL
</a>
database using the
<a>
Psycopg 2
</a>
adapter, and you want to run a query to get all the users with a given role or set of privileges. You come up with one of the following queries:
</p>
<code-block>
<div>
<span>
<span>
Language:
</span>
Python
</span>
<div>
</div>
</div>
<div>
<div>
<pre>
<span>
</span>

</span>

<code>

</p>
<div>

<strong>

The code in the above example doesn’t run because of the missing
<code>
psycopg2
</code>
library and the assumption of a certain database structure and setup. It’s a demonstrative code example only.

<p>
To avoid the risk of SQL injection, you can use the
<code>
%
</code>
operator syntax to build the query template and then provide the query parameter as the second argument to the
<code>

</code>

</p>

</span>

</span>

</span>

<code>

</code>

<code>
.execute()
</code>
. In this case, the database system will use the specified type and value of
<code>

</code>
when executing the query. This practice offers protection against SQL injection.
</p>
<div>
<p>
<strong>
Note:
</strong>
You should only use the modulo operator syntax in the string literal that represents the query template. You shouldn’t use the operator and the actual sequence of parameters to build the final query. Just let
<code>

</code>
do the hard work and build the final query for you in a safer way.
</p>
</div>
<p>
In short, you must avoid using any string interpolation tool to build dynamic queries beforehand. Instead, use the
<code>
%
</code>
operator syntax to build the query template and pass the query parameters to
<code>
.execute()
</code>
in a sequence.
</p>

<h2>
Frequently Asked Questions
<a>
</a>
</h2>
<p>
Now that you have some experience with Python f-strings, you can use the questions and answers below to check your understanding and recap what you’ve learned.
</p>
<p>
These FAQs are related to the most important concepts you’ve covered in this tutorial. Click the
<em>
Show/Hide
</em>
toggle beside each question to reveal the answer:
</p>
<div>
<div>
<p>
</p>
</div>
<div>
<div>
<p>
An f-string, or formatted string literal, is a way to include expressions inside string literals using curly braces
<code>
{}
</code>
. Introduced in Python 3.6, f-strings allow for more readable and concise string formatting and interpolation, and provide a more efficient alternative to older methods like the modulo (
<code>
%
</code>
) operator and
<code>
.format()
</code>
method.
</p>
</div>
</div>
</div>
<div>
<div>
<p>
</p>
</div>
<div>
<div>
<p>
To write an f-string in Python, you need to add an
<code>
f
</code>
or
<code>
F
</code>
prefix before the string literal. Inside this string literal, you can include variables, objects, and expressions in curly braces.
</p>
</div>
</div>
</div>
<div>
<div>
<p>
</p>
</div>
<div>
<div>
<p>
You can format numbers in f-strings by using format specifiers inside the curly braces. For example, you can use
<code>
:.2f
</code>
to format a floating-point number with two decimal places.
</p>
</div>
</div>
</div>
<div>
<div>
<p>
</p>
</div>
<div>
<div>
<p>
Yes, you can embed almost any Python expression in f-strings, including calculations, list comprehensions, and method calls.
</p>
</div>
</div>
</div>
<div>
<div>
<p>
</p>
</div>
<div>
<div>
<p>
F-strings provide a few advantages over the
<code>
%
</code>
operator and the
<code>
.format()
</code>
method. They are more readable and concise because you can directly embed variables and expressions within the string. They are also faster and more efficient in programs that deal with a large number of strings.
</p>
</div>
</div>
</div>
<div>
<div>
<p>
</p>
</div>
<div>
<div>
<p>
Before Python 3.12, f-strings had several limitations: they didn’t support the use of backslashes in embedded expressions, the reuse of the same type of quotation marks for nested f-strings, or comments within expressions. These limitations were addressed in Python 3.12, enabling more flexible and complex expressions.
</p>
</div>
</div>
</div>
<div>
<div>
<p>
</p>
</div>
<div>
<div>
<p>
You should avoid using f-strings when you need lazy evaluation, such as in logging, where the string should only be constructed if the log level warrants it. Additionally, avoid using them in SQL queries to prevent SQL injection risks. For internationalization and localization tasks, it’s better to use the
<code>
.format()
</code>
method.
</p>
