On the Quiet Joy of Static Sites

The web used to be made of files. You wrote HTML, you put it on a server, and someone, somewhere, read it. There was no build step. There was no framework. There was, mercifully, no JavaScript.

Static sites are a return to that idea — but with the modern conveniences that make it less painful: templates, partials, a content directory, maybe a CSS bundler if you must.

Why bother

You bother because the alternative is a stack so deep that nobody on your team can explain it on a whiteboard. You bother because you want to be able to read your own site in ten years.

What you give up

You give up real-time data. You give up server-side personalization. For most blogs, this is a feature, not a bug.

  • No login wall
  • No tracking pixels you didn't ask for
  • No "loading skeleton" on first paint

The cost: you can't easily add comments without bringing in a third party. So don't add comments. Email is fine.
